# 損失回避チェック (Ch1〜Ch10) — 自動と人の分担

`claude/loss_avoidance_principles.md` の「5. 日々使うチェック項目」のうち、プログラムで計算できる部分を `src/check.js` にした。
プログラムは**数値と事実を出すだけ**で、買う・見送る・外すの結論は出さない。結論は人が決める。

## 使い方

```
npm run check -- --code 6861
npm run check -- --code 6861 --amount 3000000 --buy 52000 --stop 10,15 --swing 100000
npm run check -- --code 6861 --amount 6000000 --with 7203,8035
npm run check -- --code 6861 --json
npm run test:check        # DB なしの単体テスト
```

DB は SELECT のみ。書き込みはしない。

## 分担表

| Ch | 自動(プログラム) | 人が判断 |
|---|---|---|
| Ch1 下がる側を先に書く | なし | 次の行動への条件、受け入れる最悪の損失 |
| Ch2 13週のボラ | 直近13週の週次ボラ、検証資料の群との近さ、投資額あたりの1週の動き | その動きを受け入れるか |
| Ch3 下げた銘柄を「底」と呼ばない | 250営業日高値からの下落、13/4週・20日リターン、「−15%以下」に当たるか、参考の追加下落確率 | 「底」と考える理由、さらに下がったときの行動 |
| Ch4 下方修正 | 直近N日の業績予想修正の有無と修正幅(REV)、−1pt 以下の判定 | 修正の読み(一時的か構造的か)、外すか下げるか |
| Ch5 出来高急増の急騰 | 出来高倍率と5日リターンの判定(日次近似) | 急騰の理由、追いかけたい気持ち |
| Ch6 サイズはボラで割る | 1/ボラの重み・金額、許容額から逆算した投資額 | 総額、許容する損失額、集中度 |
| Ch7 損切りは固定幅 | 損切り価格、幅が週次ボラの何週分か、全量が当たった損失額 | 置くか、幅、約定しない場合の許容 |
| Ch8 損切り後に持ち直さない | /journal の過去180日の売り・損切り記録と、その後の値動き | 再び買う理由が売ったときと別か |
| Ch9 相場に居ること | 投資比率、保有銘柄中の半導体の銘柄数、TOPIX の位置 | 現金比率、全体の許容損失、下落時の行動 |
| Ch10 判断に書く値 | ボラ、250日高値からの下落、20日リターン、下方修正の有無を整形 | /journal に書き写す |

## 注意(値の尺度)

- 週次ボラ(13週)は検証資料と同じ定義。/journal の `VOL_20D_PCT`(20営業日の日次SD)とは尺度が違う。
- Ch5 は検証が週次、ここは日次の近似。
- Ch3 の追加下落確率は群の平均で、その銘柄の確率ではない。群の境界は資料に無く、「近い群」は目安。
- Ch4 は「業績予想の修正」開示を検証済みとして扱う。決算短信での予想変更は表示するが、検証の対象外と注記する。
- Ch8 の過去記録は /journal に売り・損切りの判断が入っていないと空になる(現在は BUY / PASS のみ)。
- Ch9 の半導体は銘柄数ベースで、金額ではない。タグ `jnl_held` が保有銘柄を指す前提。
