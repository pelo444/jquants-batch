# 売買記録(/journal)

自分の売買・判断・メモを貯めて、あとで自分の判断の癖を測るための画面。
`npm run web` → http://127.0.0.1:3000/journal

## なぜ作ったか

これまでの横断面検証(`claude/*_backtest.md`)では、公開データから機械的に作った銘柄選別ルールに、
事前基準を満たすものは見つからなかった。市場データは全員の判断が相殺された後の残りで、
読み取れる偏りは競争で消える。一方、**自分の判断の癖は誰にも裁定されずに持続する**ので、
少ない標本でも測れる。そのための記録。

## 画面の約束(崩すと記録の意味が消える)

| 約束 | 理由 | どこで守っているか |
|---|---|---|
| 判断(JNL_DECISION)は**追記のみ**。編集の口は作らない。訂正は新しい行で元の行を指す | 結果を見てから理由を書き換えると、記録が自分に都合よく変わる | DBのトリガー + APIに更新口が無い |
| 判断日と記録日時の差が1日を超える行に「後から記録」の印 | 後知恵が混ざった記録を見分ける | `jnl_decision_eval_v.late_entry` |
| **見送り(PASS)も書く** | 選んだ銘柄だけを見ても、選んだことの良し悪しは分からない | 画面の文言 |
| 保有の表は持たない。約定から毎回計算する | 二重管理にすると必ずずれる | `journalPositions.js` |
| 写真は長辺1600pxのJPEGに縮めてから送る | 容量と、位置情報などのEXIFを残さないため | `journal.js` の `resizeImage` |
| 127.0.0.1 以外で待ち受けるなら認証が先 | 個人の財務情報 | `server.js` の警告 |

## 初回のセットアップ

1. `ddl/26_trading_journal.sql` の1〜4節を **GD_JQUANTS** で実行する
   (SQL Developer なら「スクリプトの実行(F5)」。トリガーは `/` で区切ってある)
2. 同じファイルの5節(シノニム)を **CLAUDE_RO** で接続し直して実行する
   (GD_JQUANTS のままだと ORA-01471。先に `SELECT USER FROM dual;`)
3. 「調べたいこと」を使うなら `ddl/27_journal_questions.sql` も同じ要領で流す(1〜2節を GD_JQUANTS、3節を CLAUDE_RO)。
   流していなくても他のタブは動く(「調べたいこと」タブだけエラーになる)
4. `npm run web` を再起動し、http://127.0.0.1:3000/journal を開く

依存パッケージの追加は無い(express・csv-parse・oracledb は既存)。

## 日々の使い方

- **約定の取込**: 楽天証券 → 口座管理 → 取引履歴 → 国内株式 で期間を指定してCSVをダウンロード →
  「約定の取込」タブで選ぶ → プレビューを確認 → 取り込む。
  - 期間が重なるCSVを入れても、同じ約定は二重に入らない(行の内容のハッシュ + 同じ内容の何件目か)
  - 解釈できない行が1行でもあれば取り込まない(プレビューに行番号が出る)
  - 知らない列は捨てずに `JNL_TRADE.RAW_JSON` に残る
  - 楽天のCSVは約定日の範囲で切り出す前提(同じ日の約定は常に全部入っている)
- **判断**: 売買のその時に書く。保有の行の「判断を記録」から銘柄を入れた状態で開ける。
  見送りも書く。あとで「振り返りを書く」(理由が当たっていたかを、値動きの結果とは分けて)。
- **メモ**: 本文・関連銘柄・写真。iPhone の写真は AirDrop で Mac に送ってから選ぶ。
  HEIC は Chrome で読めないことがあるので、その場合は Safari で開くか JPEG で共有する。
- **口座**: 週1回ほど現金と株式評価額(「保有から入れる」で計算値を入れられる)、入出金。

## 調べたいこと(`JNL_QUESTION`、ddl/27)

判断やメモを書いている途中で出てきた問いを書き留め、自分で調べるか Claude に頼むかを決め、答えも同じ行に残す。
判断と違って**編集できる**(状態・担当・答えは後から変わるもの)。

- **書き留め方は3通り**
  - 判断・メモのフォームの下の「調べたいこと」欄: 判断・メモを保存すると一緒に保存され、その判断・メモに紐付く。
    銘柄と日付は判断・メモから引き継ぐ(Enter でも追加できる)
  - 保存済みの判断・メモのカードの「調べたいことを追加」: 紐付けた状態で「調べたいこと」タブのフォームが開く
  - 「調べたいこと」タブのフォームに直接
- **1つの行に1つの問い**。「なぜ知りたいか・答えをどう使うか」を書くと、調べる範囲がぶれない
- 状態: 未着手 → 調査中 → 答えあり / 見送り。答えを書くと自動で「答えあり」になる
- タブの数字は未完了(未着手・調査中)の件数。判断・メモのカードには紐付いた問いの件数が出て、押すとその問いだけを表示する

### Claude に頼む手順

1. 担当を「Claude」にして書き留める
2. Claude に「調べたいことを見て」と頼む。Claude は CLAUDE_RO で
   `SELECT * FROM jnl_question WHERE assignee = 'CLAUDE' AND status IN ('OPEN','DOING')` を読み、
   調べた結果を作業フォルダの `answers.json` に書く:
   `[{ "questionId": 3, "answer": "...", "answerRef": "URL や claude/xxx.md" }]`。
   長い調査は project の資料(`claude/*.md`)にして、答えには要点と資料名を入れる
3. 「調べたいこと」タブの「Claude の回答を取り込む」を押す。**答えが空の問いにだけ**入る(自分で書いた答えは上書きしない)。
   入った問いは「答えあり」になり、答えた人は「Claude」と記録される

検証が要る問い(「〜は効くか」など)は、これまでの検証と同じ型(事前登録 → 1回だけ判定)で扱い、答えには合否と限界を書く。

## 手書きメモの文字起こし(Claude に頼む手順)

1. 「メモ」タブの「未文字起こしの写真を書き出す」を押す
   → `../journal_work/`(= `/Users/pelo8/apps/jquants/journal_work/`、リポジトリの外)に
   `image_<id>.jpg` と `index.json` ができる
2. Claude に「journal_work の写真を文字起こしして」と頼む。Claude が同じフォルダに
   `transcriptions.json`(`[{ "imageId": 12, "text": "..." }]`)を作る
3. 「transcriptions.json を取り込む」を押す。**空の写真だけを埋める**(画面で直した文字起こしは上書きしない)

作業フォルダは `JQB_JOURNAL_WORK_DIR` で変えられる。

## 保有と損益の計算

- 取得単価は移動平均(買うたびに平均を取り直す)。口座区分(特定/一般/NISA)ごとに別の建玉
- 現物の買いは受渡金額(手数料・税込み)を取得額、売りは受渡金額を手取りにする
- 信用返済は CSV の受渡金額(=決済損益)をそのまま実現損益にする。現引は建単価で現物に移す
- **楽天は株式分割で増えた株を「入庫」(取引区分は空)で記録する**。DB の分割日の前後10日以内に同じ銘柄の入庫があれば、
  分割は証券会社の記録に反映済みとみなし、入庫は取得費0で株数だけ増やす(その分割は AdjFactor の換算から外す。二重に数えないため)。
  入庫の株数が「保有 × (1/AdjFactor − 1)」と合わなければ警告。分割と対応しない入庫は移管とみなし、CSVの単価を取得単価にして警告
- 入庫で反映されていない分割(CSVの期間より後の分割など)は、AdjFactor で今の株数に直す(画面に「分割調整」の印)
- CSVの期間より前に買った株を売ると「確認が必要な約定」に出て、その売りの損益は「不明」になる。
  **最初の取込は、今の保有を全部買った日を含む期間で**ダウンロードすること

## 判断の評価(`JNL_DECISION_EVAL_V`)

判断ごとに株価から自動で付く。基準は判断日以前で最後の終値。

| 列 | 意味 |
|---|---|
| `VOL_20D_PCT` | 直前20営業日の日次リターンの標準偏差(%) |
| `RET_20D_PRE_PCT` | 直前20営業日のリターン |
| `DD_250D_PCT` | 250営業日高値からの下落 |
| `TURNOVER_20D_OKU` | 直前20営業日の平均売買代金(億円/日) |
| `EXR_20D_PCT` / `EXR_60D_PCT` | 20/60営業日後(約4週・13週)のリターン − 同じ日付の TOPIX。未到来なら NULL |

分割調整済みだが、**業種・規模は揃えていない**(検証の `EXR_IS` とは物差しが違う)。粗い目安として使う。
CLAUDE_RO から SELECT できるので、標本が溜まったら「理由の分類別」「確信度別」「状態別」「見送りとの比較」を
これまでの検証と同じ型(事前登録 → 1回だけ判定)で見る。目安として、分類ごとに30件程度は欲しい。
