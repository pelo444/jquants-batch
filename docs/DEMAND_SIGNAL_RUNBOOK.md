# 需給シグナル検出 運用手引き

`queries/sql/demand_signal_detection.sql`(第三階層)を日々使うための手引き。
設計の経緯と判断基準、実行の順番、読み方をまとめる。

**関連**: `docs/PROJECT.md` 9章 / `queries/sql/demand_watchlist_sheet.sql`(第二階層) /
`queries/sql/demand_macro_dashboard.sql`(第一階層) /
`queries/sql/demand_signal_backtest.sql`(検証)

---

## 0. 大前提

**SIGNAL_SCORE は「買いシグナル」ではない。「先に中身を見る順番」でしかない。**

需給5指標の予測力は10年分で検証済みで、いずれも先行リターンの方向を予測できなかった
(`demand_signal_backtest.sql`)。さらに手元のデータは上昇相場10年分しかなく、
上昇依存の手法は反証できない。**点灯は「調べる理由」であって「買う理由」ではない。**

## 1. 試行錯誤のまとめ(2026-09-14)

### 何をどう変えたか

| | 当初(書籍の値) | 現在 | 変えた理由 |
|---|---|---|---|
| S1 出来高急増 | 20日平均の2.0倍 | **2.0倍のまま** | 分布を見たら妥当だった。一度「死んでいる」と誤判定して撤回 |
| S2 | 信用倍率 <= 1.0 | **売残 ÷ 過去13週平均 >= 2.0**<br>かつ 売残 >= 過去52週中央値 | 2度作り直した(下記) |
| S3 大量保有 | 14日以内に提出 | 14日以内 **かつ 実質的な報告**<br>(変化幅1pt以上/新規/退出/割合なし) | 21銘柄中6銘柄が常時点灯して絞り込みにならなかった |
| S4 空売り残高 | 発行済の5%超 | **2%超 かつ 報告が180日以内** | 5%では点灯0件。鮮度の窓が無く古い報告で誤点灯していた |

### S2 を2度捨てた経緯

1. **信用倍率 <= 1.0** … 中央値が銘柄間で 2.43〜1573.5(**3桁違う**)。
   21銘柄中13銘柄は2年間一度も1.0倍以下にならない。点灯首位のサンドラッグは
   優待銘柄で、つなぎ売り週を除くと5%点が1.7倍に跳ねる。**実質「優待銘柄検出器」**。
2. **days to cover** … 21銘柄の最大値が2.19で、しきい値5.0に誰も届かず。
   信用売残は個人中心で、大型株では日々の出来高に対して極端に小さい
   (信越化学 0.03日分)。**「5日」は米国株の short interest を前提にした経験則**。
   桁は1桁に改善したが、銘柄間16倍 > 銘柄内3倍でまだ足りない。
3. **売残の増加率** … S1 と同じ自己正規化の形。採用。

### 判断の型として残ったもの

新しいシグナルを思いついたときは、この順で潰す。

1. **絶対値のしきい値が効くかは「銘柄間のばらつき < 銘柄内のばらつき」で決まる**
   (各銘柄のP95の最大÷最小 vs P50→P95の中央値)。
   銘柄間が上回ったら、しきい値を探し続けずに**自己正規化された形**に作り替える。
   実務的な分かれ目は「**永久に点灯しない銘柄があるか**」。
2. **点灯0件を見ても、期待値と独立観測数を先に数える。**
   21銘柄 × 到達率5% なら期待値1.13銘柄/日で、0件になる確率は3割強ある。
   1日の結果から構造を語らない。
3. **ガードを入れたら「落としたいものを落としたか」を必ず測る。**
   減った数だけを見て「厳しいほど良い」と読まない。
4. **誤検知の定義も、その時点で計算できる量で作る。**
   全期間の中央値で「汚染」を定義したら、移動窓ではどう頑張っても検出できなかった。
5. **バケット幅が違う表は密度(件/単位)に直してから比べる。**
6. **窓の定義を仮定したまま「影響が無い」と結論しない。**
   つなぎ売りの窓を決め打ちして「汚染なし」と出した後、決め打ちせずに測り直した。

### 実際にやらかした誤り(繰り返さないために)

- S1 を1日の結果で「構造的に死んでいる」と判断した(分布を見ずに)
- つなぎ売り汚染を自分で決め打ちした窓で測って「無い」と結論した(窓を検証せずに)
- 52週**平均**のガードを効果を測らずに実装した(7銘柄中5銘柄が落ち、
  落とすべきでない銘柄まで消えた。平均は裾に引っ張られる → 中央値に変更)
- DTC(売残÷出来高)を「水準が平常か」の物差しに使った
  (比率は分子と分母が同率で動くと水準変化を打ち消す → 株数の中央値で見る)

共通点は**仮定を置いた箇所を測らないまま先に進んだこと**。

### 残っている既知の弱点

- **検出不能な誤点灯が約1割**。売残が1年下がり続けた銘柄で倍になったケースは、
  どんな移動窓でも「水準が低い」と判定できない(そもそも誤検知かも怪しい)。
- **`MARGIN_SEASON_WARN` は未検証**。3月・9月の15日以降の申込分で初めて立つ。
- **つなぎ売りの季節性はリストの顔ぶれ次第**。いまの21銘柄はほぼ優待の無い
  大型株なので見えないが、優待銘柄を入れたら復活する。
- **S2(売残の増加率)は予測力を検証していない**。検証済みなのは信用倍率の水準と乖離。

## 2. 日々の実行順

実行は `node scripts/claude-query.js --file queries/output/signal_detection_XX.sql`。
単文ファイルは `queries/sql/demand_signal_detection.sql` から生成したもの(gitignore対象)。

### 毎日(日次バッチのあと。J-Quants は17:30以降、cron は18:30)

| 順 | ファイル | 見るもの |
|---|---|---|
| 1 | `01_freshness` | 取込が止まっていないか |
| 2 | `02_watchlist` | ウォッチ21銘柄の点灯 |

**1 を飛ばさないこと。** シグナルは最新値で判定するので、どれか1つでも取込が
止まっていると静かに誤判定する。

**毎日変わるのは S1(出来高)・S3(大量保有)・S4(空売り)だけ。**
S2 は信用残が週次(申込日=金曜)なので**週1回しか動かない**
(2026-09-25 申込分以降は日次化される)。

### 週1回(または気になったとき)

| 順 | ファイル | 見るもの |
|---|---|---|
| 3 | `04_supplementary` | days to cover・日々公表銘柄・空売り報告者数の増減 |
| 4 | `03_all_codes` | ウォッチリスト外からの候補(2つ以上同時点灯のみ) |

03 は全銘柄 × 15か月の信用残を走査するので重い。毎日流す必要は無い。

### 四半期ごと、またはウォッチリストを入れ替えたとき

較正クエリ 05〜11。**ウォッチリストの顔ぶれが変わるとしきい値の前提が変わる**ので、
銘柄を足し引きしたら流し直す。

| ファイル | 決めること |
|---|---|
| `05_calib_volume` | S1 のしきい値(出来高倍率の分位) |
| `06_calib_margin` | (旧S2の経緯。判断の記録として残してある) |
| `07_calib_lvs_change` | S3 の変化幅しきい値(大量保有の変化幅分布) |
| `08_calib_dtc` | (days to cover を捨てた経緯) |
| `09_calib_shrt_mult` | S2 のしきい値(売残倍率の分位) |
| `10_calib_seasonality` | つなぎ売りがいつ効くか(月 × 月末までの週数) |
| `11_calib_baseline_window` | S2 の基準窓と水準バーの当否 |

## 3. 02 の読み方(列を見る順番)

### Step 1: まず「疑う列」を見る

点灯した行を上から読む前に、その点灯が信用できるかを先に確かめる。

| 疑う列 | 何を疑うか |
|---|---|
| `SPLIT_FLAG = 'Y'` | 20日以内に分割。出来高の株数基準が変わっているので S1 を疑う |
| `MARGIN_SEASON_WARN = 'CROSS'` | 3月・9月のつなぎ売り。S2 を疑う |
| `AVG_VOL_N < 20` | 20日平均が成立していない(上場直後・売買停止明け) |
| `MARGIN_SHRT_N_13W < 13` | 売残の基準が揃っていない。S2 は対象外になっている |
| `SHORT_DAYS_SINCE` が大きい | 空売り報告が古い。180日超なら S4 は立たない |
| `LVS_GRP_CNT_STALE` が多い | 大量保有の合計が過去の姿 |
| `MARGIN_SHRT_VS_13W` が2桁 | 上場直後などで基準が小さすぎる。水準を見る |

### Step 2: シグナル別の見方

| シグナル | 一緒に見る列 | 判断 |
|---|---|---|
| 出来高急増 | `VOL_VS_20D` / `AVG_VOL_N` / `SPLIT_FLAG` | 倍率の大きさと、平均が成立しているか |
| 売残の増加 | `MARGIN_SHRT_VS_13W` / `MARGIN_SHRT_VS_MED52` / `MARGIN_SEASON_WARN` | 直近比と長期比の**両方**が高いか。片方だけなら弱い |
| 大量保有提出 | `LVS_RECENT_SUMMARY` **必読** / `LVS_RECENT_MATERIAL` | **向きを必ず読む。退出でも点灯する** |
| 空売り残高過大 | `SHORT_RATIO_PCT` / `SHORT_DAYS_SINCE` / `REPORTER_COUNT` | 報告者が増えているほど売り方の関心が強い |

**`LVS_RECENT_SUMMARY` を読まずに `SIGNAL_SCORE` だけで判断すると向きを取り違える。**
`[形式的]` が付いている報告は実質的な売買ではない(判定からは既に外れている)。
`LVS_RECENT_DOCS > 0` なのに `LVS_RECENT_MATERIAL = 0` の行は「報告は出たが動きは無い」。

### Step 3: 深掘り(気になった銘柄だけ)

| 知りたいこと | 見るところ |
|---|---|
| いま誰が何%持っているか | `demand_watchlist_sheet.sql` の **7**(銘柄指定)。提出者の正式名称もここ |
| その銘柄の需給の推移 | `demand_watchlist_sheet.sql` の **3**(週次時系列、銘柄指定) |
| 大量保有の全履歴 | `demand_watchlist_sheet.sql` の **4**(銘柄指定) |
| 市場全体の地合い | `demand_macro_dashboard.sql` |
| 踏み上げの燃料 | `04_supplementary` の `DAYS_TO_COVER` / `DAILY_PUBLICATION` |

## 4. 数字を鵜呑みにしない列

**NULL や 0 が「ゼロ」を意味しない列がある。** グラフでは0でプロットせず線を切る。

| 列 | 見え方 | 本当の意味 |
|---|---|---|
| `SHORT_RATIO_PCT` が NULL | 空売りが無い？ | **0.5%以上の報告が無いだけ。大型株ほど起きる** |
| `SHORT_RATIO_PCT` が 0.00 | 残高ゼロ？ | **0.5%を割ったことを知らせる最終報告**(`SHORT_STATUS='報告終了'`) |
| `LVS_GRP_CNT = 0` | 大量保有者がいない？ | **この5年で動きが無かっただけ**(取込は2021-07-01開始) |
| `LVS_TOTAL_PCT` が空 | 保有割合ゼロ？ | 割合の記載が無い書類(`LVS_GRP_CNT_NORATIO` に件数) |
| `MARGIN_*` が NULL | 残高ゼロ？ | 営業日2日以下の週(GW・年末年始)は**JPXが公表しない** |
| `LVS_OUT_STKS_AT_DOC` | 現在の発行済株式数？ | **その書類時点の株数**。分割前の書類は旧株数 |

`01_freshness` の `DAYS_BEHIND` も同様で、**信用取引残高は0〜11日が正常**
(週次・翌週第2営業日公表)。バッチの停止と読み違えないこと。
株価・空売り・大量保有は0〜3日を超えたら疑う。

## 5. 点灯を記録すること

**1日の結果からは何も言えない。** 点灯した銘柄・日付・シグナルの内訳を控えて、
後から「あの点灯は何だったのか」を振り返れるようにしておく。
点灯率が想定(S1・S2とも約5%、21銘柄なら合計で毎日1〜2銘柄)から大きく外れ続けるなら、
しきい値ではなく**データか前提のほうを疑う**。

調査メモは `trend_analysis/*.md` に残す(`docs/PROJECT.md` 8.4)。
